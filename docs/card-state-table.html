AWrapper uses inset:0 until expandedDimensions is set (M5). Before that, wrapper dimensions = card DOM dimensions.
BisAnimating is set in useEffect, which fires after paint. On frame 0 of any isExpanded change, isAnimating is still false. On frame 0 of collapse (M6), !isExpanded && !isAnimating = true — the collapsed content mounts simultaneously with the exiting wrapper for one frame before the effect fires and sets isAnimating=true.
CExact corrective scale ≈ (before rect) / (after rect) per axis. On expand: ~0.45–0.5. On collapse: ~2.0–2.2. Value varies by column count, grid gap, and card position.
DisAnimating remains true until its setTimeout fires at duration.slow from isExpanded→true. M4 is defined as just before isStable flips, meaning the timer is about to fire but has not yet.
EexpandedDimensions is set in an effect triggered by isStable→true. Between M4 (isStable flips) and M5 (effect fires, dims measured), there is one render where isStable=true but expandedDimensions=null. The style is not yet applied.
FOnce expandedDimensions is set, the wrapper style gains right:auto, bottom:auto, width:W, height:H. This overrides the CSS inset:0 on the right and bottom axes. While the card is still open (isExpanded=true), the card is also W×H, so the visual result is identical to inset:0. The fixed dims only have visible effect during the exit (M6–M8).
Gfootprint clears to {} on the same render frame that isExpanded becomes false. The card's DOM moves to 1×1 immediately. FLIP captures both the 2×2 before-rect and 1×1 after-rect in the same commit. No holdFootprint equivalent — the before-rect is captured by Framer Motion's layoutEffect before DOM paint.
HexpandedDimensions is still set at this moment (cleared by timer at duration.slow). Wrapper holds W×H despite card DOM being 1×1. Card's overflow:hidden clips wrapper to card's visual bounds, which are W×H at FLIP start due to the scale(~2.0) corrective.
IAnimatePresence holds the wrapper for the exit animation: exit={{ opacity: 0, scale: 0.95 }}. The opacity and explicit scale begin animating on this frame.
JCSS transforms apply to all descendants. The card's corrective scale(~2.0) is inherited by the wrapper and its content. At M6, the content is at full opacity — unlike expand (M2) where opacity:0 hides the distortion. The 2× inherited scale is immediately visible before the exit opacity fade has time to cover it. This is the identified problem: the open direction benefits from an opacity gate that the close direction lacks.
KAnimatePresence holds the wrapper in the DOM until its exit animation completes. The timer that clears expandedDimensions fires at duration.slow — the same duration as the exit animation. The wrapper may still be technically mounted at this moment (rAF vs setTimeout race) with the exit complete visually but not yet unmounted.
isStable / isAnimating M7–M8Both timers fire at duration.slow from isExpanded→false. They are set in the same useEffect callback but are separate setTimeout calls. Execution order between the two is indeterminate. isStable should be false after the timer fires; isAnimating should be false. At M8 (animation visually complete but timer not yet fired) both should still be in their previous state — but the exact moment "animation visually complete" maps to depends on rAF scheduling.
LIn the target implementation there is no M9 discontinuity. The card's FLIP resolved to 1×1 during M6–M8. The grid is already in its resting state. No scale snap, no second FLIP trigger. Collapsed content fades in smoothly once isAnimating clears.
