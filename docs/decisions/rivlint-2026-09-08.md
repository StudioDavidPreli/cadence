# rivLint, the public .riv linter (build-order item 9)

Decision record for the rivLint page (`#/tools/rivlint`,
`src/components/RivLint/`), written 2026-09-08 at the close of the build.
The probe that preceded it ran 2026-09-07; David settled the gate on
2026-09-08 and reshaped its first question; the model shipped that morning
and the page that afternoon, each after his review. The running record is
the tracker's item 9 entry; this document keeps the decisions and what they
cost. The name is rivLint, lowercase r held even at the start of a sentence;
the title art sets it as .rivLint.

## What it is

Drop a .riv and read what a runtime will find in it. The page loads the
file through the same webgl2 runtime the site runs on, inside the page, and
reports the facts a consumer needs before anything else: the artboard a
load that names none will draw, the view model that artboard binds by
default, its state machines and their inputs, and every view model with its
properties and named instances. Under that, findings; under those, an
inventory in closed disclosures; then a preview, a compare zone that takes
an earlier export or an earlier report, and a download of the report as
JSON. Nothing about the file leaves the browser, and the e2e suite asserts
a network log that is empty outright during a lint, not even a `blob:`
URL.

The question the page exists to answer is the one a re-export raises too
late. A Rive file gets opened, touched, and saved again, and the editor
gives no diff. On 2026-07-09 tile r4c1 shipped blank because its view model
link did not survive an export; the grid's own diagnostic caught it. The
site's contract gate (`e2e/rivlint.spec.js`, item 1) was built to catch
that class on the shipped files. rivLint is that gate behind a public page,
for anyone's file.

## The read

Four decisions, all from the probe (below), all in `readRiv.js`:

- **Bytes in, never a URL.** The dropped file is read as an ArrayBuffer and
  passed as `buffer`. Measure filters the video element's own `blob:` URL
  out of its network assertion; rivLint has nothing to filter.
- **The asset CDN off, and a loader that claims every asset.** With the
  runtime's defaults a file carrying hosted assets fetches them from
  `public.uat.rive.app` at load, which would carry the file's asset ids off
  the page. The loader callback is also the only surface that enumerates
  assets, so claiming them is how the report learns what the file carries:
  name, kind, and whether it is embedded, referenced, or hosted.
- **One load reads almost everything.** `contents` gives every artboard's
  timelines, state machines and inputs from one load, the view models and
  enums are on the same instance, and `activeArtboard` on a load that names
  no artboard is the file's default artboard, which is a property of the
  file (the editor's "set as default"), not a position in the list. David's
  correction, 2026-09-08; the first draft assumed the first listed, which
  happened to hold in all 48 probe files and all 74 site files, and is now
  an observation the code does not rely on.
- **Per-artboard default view models cost a load each.** `defaultViewModel()`
  answers for the loaded artboard only. The page reads the first twelve and
  lists the rest as unread rather than stall on a forty-artboard file.

## Decisions

**No house convention is checked.** The kickoff proposed Cadence's own
contracts as named profiles (principle art, display title, tile). David cut
them at the gate: "no one cares about my own internal conventions; the tool
lints against industry standards or a user's definition in a previous
report." The landscape agrees. Four free browser inspectors already read a
.riv (rivinspect.dev, rive.best, riveviewer.com, rivein.dev); the three that
could be read enumerate structure, some generate code stubs, and none runs a
rule, compares two files, or exports a comparable report. An inventory page
would have been a fifth viewer. The site's own conventions stay in the e2e
manifest, one user's contract run by that user's suite, which is the same
mechanism the page offers everyone.

**Nine rules, three severities, each cited.** Fail is what breaks any
consumer: the default artboard binding no view model while the file has
one (the runtime's autoBind finds nothing and draws the artboard with no
instance), and duplicate names at any level the runtime addresses by name
(it resolves to the first match). Warn is a cost the consumer must plan
for: a hosted asset, a referenced asset, an asset embedded more than once
(one of Rive's own examples carries Inter three times, 2.6 MB of a 2.7 MB
file), an embedded font over 500 kB (Rive's guidance is to subset glyphs).
Note is hygiene: the editor's default names on anything addressed by name
(over a hundred hits in the probe set, hence a note), a view model with no
named instance, an artboard with no state machine. The editor's implicit
instance has the empty string for a name, seven of the probe's files carry
one, and it counts as no named instance. Our own tiles carry "Timeline 1",
and the page says so on a Cadence file.

**The report leads with the handoff.** David's addition at the gate: before
any rule, the default artboard, its default view model, its state machines
with inputs, and every view model's properties with types. The names a
consumer writes, in the order they write them.

**Contract mode is superset.** A previous report dropped as "check against"
is the expected definition. Everything it names must still be present with
the same type and each artboard's default view model must match; anything
the file gained is listed and does not fail. That is how a consumer's code
breaks: a re-export that adds a property is harmless, one that loses or
retypes anything is not. The compare zone tells a .riv from a report by the
first four bytes, "RIVE" or "{", because a browser download lands under a
bare temp name and the first draft, keyed on the extension, read the report
as a corrupt .riv.

**The diff keys by name at every level**, so a renamed artboard reads as
one vanished and one appeared, which is honest if noisy. Sections one side
does not carry are skipped: a bare manifest entry knows nothing about
inputs, enums or assets, and the diff must not report that ignorance as a
change.

**One report shape, three uses.** `{ meta, inventory }`: file name, size,
runtime version and date on top; the inventory under it. Projected onto the
manifest's keys it is a valid row for `e2e/rivlint/manifest.json`; dropped
back on the page it is a diff or contract input; downloaded it is the record.

**The samples show the workflow, not the conventions.** Two buttons load a
shipped file (a principle icon, a Glossary title) paired with the report the
page produced from it earlier, built by a script from the same read, so the
first click is a passing contract check. The e2e warms the runtime on a
sample before it watches the network log on a file-input lint, so the WASM
fetch (this origin, never carrying the file) is behind the assertion and
the log can be asserted empty.

**The preview binds explicitly.** One artboard, its first state machine, one
named instance chosen from the artboard's default view model or the file's
first, bound through `bindViewModelInstance` with autoBind off, the way the
probe showed a file whose artboard lost its default pointer still draws when
told what to bind. No autoplay under reduced motion; a play control instead.
The render check the kickoff proposed (bind every instance, hash the
pixels, all-same means unbound) is written, works on the negative case, and
is deferred: the failure class it was for turned out to be structural.

**Placement and name.** The second leaf under Tools, David's 2026-09-05
section; route `#/tools/rivlint`, lazy chunk (35 kB, 10 kB gzipped), tool
bar railed, outside MotionTokensProvider. The name came from a workshop the
same day. Not "Inspect": two existing tools own the word and inspecting is
the viewer half. "Riv" rather than "Rive" because the qualifier names the
file the tool accepts, not the company, and the gate had called itself
rivlint since item 1. Nothing called rivlint existed anywhere the search
could see. The title is David's `rivlintTitles.riv` on the display-title
convention (artboard `rivLintTitles`, state machine `rivLintSM`, view model
`RivLintTitleVM`, four per-theme instances), posters under reduced motion.

## The probe, and what it changed

Before the gate, 47 files went through the runtime in a Playwright harness:
35 from Rive's own repositories (the react and wasm examples, the runtime's
unit-test assets), committed between May 2022 and four days before the
probe, and 12 of David's from outside the site. Every one loaded. Load time
was single-digit milliseconds for most; the slowest, a 25-artboard 1.5 MB
file, took 974 ms. Eleven of the thirteen property types appeared. Text
runs, artboard nesting, scripts, listeners, converters and shape bindings
were confirmed invisible; a nested view model's properties are reachable
through an instance and its name is not readable anywhere. Eighteen of the
47 carried no view model at all, which is why the diff keys artboards and
inputs and assets and not only view models.

The probe's largest finding arrived the next day. David broke a copy of
r4c1 in the editor and exported it. On every key the manifest recorded, the
broken file was identical to a healthy tile: one artboard, one state
machine, PathEffectVM with its three instances and thirteen properties, in
the same order. The gate would have passed it. What the export had lost was
the artboard's default view model assignment; `defaultViewModel()` read null
where the healthy file read PathEffectVM. Bound explicitly, the broken file
drew the same three frames, hash for hash, as the healthy one, so the
property-to-shape bindings had survived. The break was one pointer, and it
is exactly the pointer autoBind follows. The gate gained per-artboard
default view models the same day (`f6a2647`), then the file's default
artboard (`d4f0527`); a baseline doctored to the broken shape fails naming
the file and the key. The founding incident, reproduced, explained, and
pinned, two months after it happened.

## Limitations

- **A file newer than the runtime's format** fails to load, and no specimen
  exists: every probe file loaded, and a fresh export from an editor ahead
  of runtime 2.38.4 was not available. The report prints the runtime version
  it read with, and the load error names the possibility.
- **Shape bindings are invisible.** A property-to-shape binding that broke
  while the view model and its default pointer survived reads clean here.
  The not-seen line says so on every report. The pixel-hash render check is
  the candidate and waits for a specimen.
- **Nested view models show their properties, not their names.** A `list`
  property shows nothing about its item view model without an instance
  holding items.
- **Per-artboard default view models stop at twelve.** The status line
  names how many artboards were not opened.
- **The diff does not follow renames.** One vanished, one appeared.
- **Input types are the runtime's numeric codes** (56, 58, 59), mapped to
  words by the page; a code the map does not know is shown as its number.
- **The default artboard is the file's property**, read from `activeArtboard`.
  Two artboards sharing a name would read the same answer, and the
  duplicate-name rule fails such a file first.
